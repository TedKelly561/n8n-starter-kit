# Server security

The kit itself only publishes ports 80 and 443 (Caddy). Postgres has no published port
and sits on an internal-only Docker network. All passwords and keys are generated by
`setup.sh`; there are no defaults. The rest is the server's job.

## 1. SSH keys only

On your own computer:

```bash
ssh-keygen -t ed25519 -C "you@example.com"
ssh-copy-id root@203.0.113.10        # your server's IP
```

On the server, after checking key login works in a second terminal:

```bash
sudo sed -i 's/^#\?PasswordAuthentication .*/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo sed -i 's/^#\?PermitRootLogin .*/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config
sudo systemctl reload ssh
```

Better still, create a normal user, add it to the `docker` and `sudo` groups, and set
`PermitRootLogin no`.

## 2. Firewall (UFW)

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 443/udp               # HTTP/3, optional
sudo ufw enable
sudo ufw status verbose
```

Note: Docker writes its own iptables rules, so a port published by a container is
reachable even if UFW does not list it. That is why the kit publishes only Caddy's
80/443 and nothing else. Do not add `ports:` to postgres or n8n.

Many providers also offer a cloud firewall: allow 22 (ideally only from your IP), 80 and 443.

## 3. Automatic security updates

```bash
sudo apt install -y unattended-upgrades
sudo dpkg-reconfigure -plow unattended-upgrades
```

## 4. n8n account

- Create the owner account right after install; until then the first visitor can.
- Turn on two-factor authentication for the owner (user menu > Settings > Personal).
- Invite people as members, not owners/admins, unless they need it.

## 5. Secrets

- `.env` is mode 600 and gitignored. Keep a copy of `N8N_ENCRYPTION_KEY` in a password manager.
- Use `BACKUP_AGE_RECIPIENT` with a public key; keep the private key **off** the server.
- Credential exports in backups stay encrypted with `N8N_ENCRYPTION_KEY`; the kit never
  uses `--decrypted`.

## 6. Optional hardening

- `N8N_SSRF_PROTECTION_ENABLED=true` blocks workflows from calling private IP ranges
  (add it under the n8n `environment:`). Leave it off if your workflows call internal
  services.
- Put Uptime Kuma behind the provided basic auth (setup does this) and its own login.
- If you put Cloudflare's proxy in front after the first certificate, set SSL mode to
  **Full (strict)**.
